# Carrier / SMS / PSTN — what Jay must choose

No signup is made here, no card is used, and the agent cannot choose a
carrier for Jay. This doc says exactly what the choice is, what each
option plugs into, and what stays internal-only until Jay picks one.

## The situation

- Internal numbers work NOW with no carrier: 1,000 extensions are
  provisioned (test run verified: 1,000 dovecot-users entries with real
  SHA512-CRYPT hashes, 1,000 credentials.json accounts, zero
  placeholders). Agents can call/message each other inside the stack
  (embedded SIP on :5060, mail on :3000/:2525).
- Public calls/SMS (a real phone number that the outside world can call
  or text) need a carrier or SIP trunk. There is no free-forever carrier;
  every public-number route below has a cost, a trial, or a bring-your-own
  number step that only Jay can do.

## Options (Jay picks one; nothing is pre-chosen)

### A. SIP trunk (recommended for this stack)

Buy a SIP trunk + DID (public number) from a SIP provider (e.g. Twilio
Elastic SIP Trunking, Telnyx, VoIP.ms — any provider that sells a trunk
with username/password auth). What it plugs into:

- `phone/sip_probe.py` target: the provider's SIP edge (host/port).
- Asterisk `pjsip.conf`: a trunk endpoint + a registration to the
  provider; inbound DID routes to the internal extensions.
- No code change: the CL server's originate path already dials via AMI;
  the trunk is an Asterisk-side config only.
- Cost: providers charge per-minute + a monthly DID fee (typically a few
  dollars/month). No card is put on file by the agent; Jay enters it in
  the provider's own signup.

### B. Twilio (or similar) programmable number + webhook

Twilio number with an SMS webhook pointing at the inbound-SMS endpoint.
What it plugs into:

- `CARRIER_HMAC_SECRET` in `/etc/linux-carrier-1000/env`: set it to the
  secret Twilio signs webhooks with (Twilio calls it the Auth Token;
  the webhook handler verifies `X-Carrier-Signature-256` HMAC-SHA256).
  Until this is set, the webhook returns 503 (fail-closed, verified by
  the security tests). Setting it is what enables the hook.
- The webhook URL itself: `https://<public-host>/api/webhooks/inbound-sms`.
- Outbound SMS: the stack sends via the provider's API; no code exists
  for that yet — it is a build step after Jay picks the provider.

### C. SIM gateway / GSM hardware (self-hosted, no monthly provider)

A USB GSM modem or SIM bank on the Linux box, driven by the stack's
`phone/` code. No monthly fee beyond the SIM plan. This is the most
self-hosted option and the most hardware-dependent; the modem must be
physically attached to the box. Only pick this if Jay already has the
hardware.

### D. Stay internal-only

No public number. Agents keep internal extensions + email only. Public
reach stays via AgentMail (already verified both directions Nov 19) and
the businesses' existing channels. This is a legitimate choice: nothing
in the stack requires a public number to work.

## What Jay must decide (one line each)

1. Public number: yes or no? If yes, trunk (A), programmable (B), or
   SIM hardware (C)?
2. If A or B: which provider, and which DID/number?
3. SMS only, calls only, or both?
4. Budget cap per month (so the provider's spend limit can be set).

## Config map (where each choice lands)

| Choice | Config destination |
|---|---|
| SIP trunk credentials | Asterisk `pjsip.conf` (trunk + registration) |
| Twilio webhook secret | `CARRIER_HMAC_SECRET` in `/etc/linux-carrier-1000/env` |
| AMI user/secret | `AMI_USER` / `AMI_SECRET` in `/etc/linux-carrier-1000/env` (generated by the installer) |
| TURN secret | `TURN_SECRET` in `/etc/linux-carrier-1000/env` (generated by the installer) |
| Public hostname/IP | `CARRIER_PUBLIC_IP` / `CARRIER_DOMAIN` in `/etc/linux-carrier-1000/env` |
| DID -> extension routing | `phone/provision.py` state + Asterisk dialplan |

## Hard limits (do not work around)

- No test accounts, no fake carrier, no simulated inbound SMS: the
  webhook rejects unsigned requests (503) and the tests prove it.
- Never put a provider secret in a repo file or chat; it goes in
  `/etc/linux-carrier-1000/env` (600) or the vault.
- Port 25 outbound and SIP 5060/UDP must be reachable from the box;
  if the VPS provider blocks them, only Jay (the account holder) can
  ask for the block to be lifted.
